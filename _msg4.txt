fix(kmod): rewrite the SCSI disk model, the last remaining tell

/sys/block/sdX/device/model read HARDDISK on all three disks. A handset's storage is UFS
behind sdhci_msm and reports a Samsung part number, so this was a desktop tell in a
world-readable file.

Nine attempts. What made it hard:

- the string is not static. scsi_scan.c does `sdev->model = sdev->inquiry + 16`, so it lives
  inside the device's heap-allocated INQUIRY buffer. Searching .rodata, then the whole kernel
  image, both found nothing.

- struct scsi_device is __randomize_layout, so no field offset can be computed, and
  to_scsi_device() is container_of(d, scsi_device, sdev_gendev) — an embedded member, not
  drvdata.

- kernfs_node->priv means three different things on the three nodes that look relevant:

      /sys/block/sda                        a disk device
      /sys/class/scsi_device/0:0:0:0        an sdev_dev (priv[0] is not a name pointer)
      storage/host0/target0:0:0/0:0:0:0     the literal 5

  So there was no reliable anchor.

- scanning a guessed window past an object faults: a qword beyond a slab allocation lands in
  unmapped memory and module_init has no exception table. Three attempts wedged the guest
  that way (±0x2000 around a priv, 0x800 forward from candidates, one unbounded pass), each
  costing a restart.

What worked was to stop guessing and use what the kernel exports:

    struct Scsi_Host *scsi_host_lookup(unsigned short hostnum);
    struct scsi_device *scsi_device_lookup(host, channel, id, lun);
    size_t ksize(const void *);

Two details decided it:

- scsi_host_lookup takes an integer, not a name. Passing "host0" as a pointer made it search
  for host 0x3068736f and return NULL — that was the last bug.

- ksize() bounds the scan. It returns the real allocation size (4096 here), so `off + 8 <=
  size` cannot leave the object. The field sits at sdev+0x100 on this build.

    sdev = scsi_device_lookup(shost, 0, id, 0);
    size = ksize(sdev);
    for (off = 0; off + 8 <= size; off += 8)
            if (is_harddisk(*(void **)(sdev + off)))
                    memcpy(*(void **)(sdev + off), "KLUDG4UHGC-B0E1 ", 16);

All three disks now report KLUDG4UHGC-B0E1, verified after a reboot so the KernelSU module
loads it at boot.

## Remaining, and it is structural

The /sys/module entries for ufs_qcom, msm_drm, arm_smmu and sdhci_msm are directories with
attributes, not drivers: /sys/module/ufs_qcom/sections/.text is empty where a handset shows a
section address. Closing that needs the driver compiled into the kernel. MuMu's source is not
public, but the kernel image was located while investigating — system.vdi at offset 0x17c0000,
12,362,752 bytes, uncompressed, version matching the guest exactly — so a replacement kernel
has a known landing site; what it cannot have is drivers that were never written.
